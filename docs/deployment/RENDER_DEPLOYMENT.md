# Backend on Render.com

The repo’s [render.yaml](../../render.yaml) defines **only the backend and PostgreSQL** for Render. The frontend is deployed on **Vercel** (see [DEPLOY.md](./DEPLOY.md)).

## What’s in the Blueprint

- **db** – Postgres instance (free tier, Oregon, PostgreSQL 15).
- **backend** – Django Docker web service: health check `/api/health/`, pre-deploy migrations.

`DATABASE_URL` is not auto-injected (to avoid Blueprint sync "id is empty" errors). You set it once in the Dashboard.

## One-time setup on Render

1. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** → connect this repo → **Apply**.
2. After the first sync, in **db** → copy **Internal Database URL**. In **backend** → **Environment** → add **DATABASE_URL** = that URL. Save (backend will redeploy).
3. In **backend** → **Environment**:
   - **CORS_ALLOWED_ORIGINS** – optional; set to your Vercel URL if you restrict CORS later.
   - **SECRET_KEY** – generated by Render.
   - Optional: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, S3/Spaces vars.

Full step-by-step (Render first, then Vercel, then CORS): **[DEPLOY.md](./DEPLOY.md)**.
